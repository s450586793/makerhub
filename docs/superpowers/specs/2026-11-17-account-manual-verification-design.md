# 首页账号人工验证弹窗

用户要求在首页国内站、国际站卡片点击“去验证”后，在 MakerHub 弹窗内人工完成验证码。

## 方案

豆瓣插件使用腾讯官方 SDK，但 MakerWorld 的 CF 与下载图形验证码绑定浏览器页面。因此采用当前 CloakBrowser profile 的专用页面，通过截图与鼠标、键盘事件交互。外部打开浏览器仍服务普通账号登录；不恢复旧 Worker proof 注入。

专用 Node bridge 持有页面，Python 后台会话持有既有浏览器跨进程锁。验证码会话绑定当前 MakerHub 登录会话，最多保留 10 分钟，同时只允许一个人工会话。取消、超时、进程退出只关闭所属页面和 bridge，保留 profile 与用户其他页面。

页面级 CF 先由用户完成。可信模型、配置与当前登录通过预检后，按照原请求间隔和额度预约触发一次下载授权；只接受相同配置的验证码续传。成功授权响应必须具有有效下载地址，且账号与 Gate 快照未变化，才解除验证 Gate 并恢复任务。用户点击完成本身不作为下载权限凭据。

## 接口与交互

`/api/config/online-accounts/{platform}/verification` 创建会话，后续 `/{session_id}/frame`、`input`、`finish` 与 DELETE 管理会话。所有接口验证当前登录身份及会话所有权，截图不可缓存，Cookie、CDP 凭据与下载直链不返回前端。

弹窗沿用现有主题 token，支持缩放画面中的点选、拖拽、触屏、滚动和文字输入。请求串行，关闭和卸载取消会话并忽略晚到结果。完成后刷新首页状态。

## 验证

覆盖跨站地址拒绝、输入范围与顺序、同一页面多次验证码响应、授权预约、会话所有权、过期与取消、账号变更不清 Gate、迟到请求清理、深浅主题构建，以及本地 Chromium 交互。真实外站验证码需用户在部署后人工验收，不能以本地 fixture 代替。
