# 浏览器页面验证与同页面请求

用户已确认将前置 CF、同页面接口读取和现有图形验证一并接入。复用 MakerHub 当前 CloakBrowser profile、代理和登录态，不增加浏览器容器或外部解题服务。

## 行为

- 页面出现明确 Cloudflare / Turnstile 或 GeeTest 信号时，先等待自然完成，再尝试当前支持的可见交互。普通网页文字、checkbox、401、403、429 不触发解题。
- 单次操作的自动验证共用 50 秒预算，每个挑战最多交互 2 次。完成必须确认拦截页面消失；3MF 还必须收到页面自身产生的成功授权响应。
- 控制面 GET 从任务自己的可见页面发出原生 `fetch`，保留 profile Cookie 和浏览器代理。明确 CF 响应时，允许同页导航受信任 origin 处理挑战，再重试 GET 一次。
- 仅允许对应平台的 HTTPS 白名单地址；在网络发出前阻断越界导航和重定向，不能向外域携带认证头。
- 控制面 URL 统一规范化后匹配；跨源 CORS 拦截正文时，仅凭明确的 CF 响应标头进入验证恢复。验证失败返回当前页实际挑战 DOM，维持既有人工分类。
- JSON 在 24 MiB 限额内完整返回；保留超时、取消和资源大小限制。普通网络错误不改用 Node / requests 回退。
- 3MF Download 仍仅点击一次，不重放授权 POST。前置验证与后置图形验证共用预算，失败保留现有人工接管和 Gate 行为。
- `MAKERHUB_AUTO_VERIFY_CHALLENGES` 与 `MAKERHUB_AUTO_VERIFY_3MF` 默认开启，均可显式关闭。支持已有 Turnstile、GeeTest 图标、按序点选和滑块；未知题型人工接管。
- 只关闭任务自己创建并登记的页面；不关闭用户页、不停止或重启共享 profile、不向关联 profile 注入旧 Cookie。

## 验收

以依赖注入单测和本地 Chromium fixture 验证，无生产请求或真实下载。覆盖自然通过、可见交互、失败人工回退、一次 GET 恢复、401/403/429 保留、跨域阻断、完整 JSON、超时和失败清理。版本升级至 0.21.0，完整 Python / frontend 测试和构建通过。本轮不推送或部署。
