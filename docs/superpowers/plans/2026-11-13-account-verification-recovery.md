# 历史站点验证暂停自动复测

问题已通过生产只读状态和代码追踪确认：国内站、国际站保存了升级前的 `verification_required`；普通账号检测不会清除 3MF 暂停，空闲补档跳过关闭的 gate，底层 pacing 也直接合成 418，因此新版自动验证没有机会处理这些历史状态。

修复复用当前 Worker、浏览器 profile、授权入口和每日额度。空闲维护期检查两个站点，找到同站有效实例后，在取得浏览器操作锁、通过请求节奏和冷却检查后，才持久预约并发送真实授权请求。预约指纹取版本、profile 和当前认证会话摘要；时间戳、定时检查或进程重启不会重新授权。缺少目标、配置关闭、手动暂停、忙碌或达到额度时保持原状态，未发送请求的本地阻断不消耗复测机会。

新增显式 `verification_probe` 只允许本次复测越过旧验证暂停，保留 profile 锁、请求间隔、429 冷却和每日限额。只有真实 2xx 授权响应中的有效 HTTPS 下载地址才允许原子清除原暂停；页面可访问、验证码完成、空 200 或本地文件已存在均不算成功。失败保留人工入口，授权结果中的凭据及签名下载地址不进入复测日志或状态。

验证按 TDD 执行，覆盖无任务队列、两站隔离、并发预约、轮询及重启不重复、空响应、失效登录态、每日限额、手动暂停、429、授权超时，以及真实 pacing 冷却结束后仍可复测的集成场景。成功后强制执行原有验证暂停恢复维护，避免继续等待十分钟维护间隔。
